# Multimodal Media Triage

Use `ctf-multimodal-triage` for image, video, and audio Misc artifacts when a vision-capable model is available. The tool returns bounded attachments plus reproducible metadata; the attachments are evidence, not a solve by themselves.

## Image

Inspect the attached original/preview together with dimensions, OCR, metadata, alpha/channel clues, QR/barcode hints, and trailing-data hints. For images at least 2400px wide or tall, the tool attempts up to four bounded 2x2 ROI tiles and opportunistic OCR on each tile; inspect these separately for tiny text, corner QR codes, and local stego patterns. When transparency is suspected, set `channelPreviews: true` to attach a bounded alpha preview; compare it with the visible composite before escalating to channel-level stego. Use `ocrLanguage` for installed Tesseract languages such as `eng`, `chi_sim`, `eng+chi_sim`, or `jpn`; the result records requested/effective languages and the installed language list. The default local `zbarimg` probe is capability-aware: a missing decoder is degraded evidence, while returned payloads remain untrusted until matched to the visible region. Ask the vision model to identify salient text, repeated pixels, suspicious regions, and visual structure. Run `ctf-stego-probe` only when visual or metadata evidence supports it.

## Video

Start with at most six evenly sampled key frames. Compare start/middle/end and record temporal changes, text, QR codes, frame-local anomalies, subtitle streams, and audio presence. OCR uses the requested `ocrLanguage` when available, and the bounded local barcode probe checks sampled frames when `barcode` is enabled; always preserve frame/timestamp provenance for decoded candidates. If a temporal clue appears, rerun with `startTime` plus `segmentDuration` (or a focused `frameInterval`) so the second pass samples the implicated time range rather than restarting at zero; interval samples are clamped to the selected segment. The returned `sampling` and `signalWindow` coordinates are evidence provenance, not just display metadata. Barcode candidates include the sampled frame filename and timestamp when available. Derived frame/signal images are attempted before attaching a large raw video, so the attachment budget favors evidence the model can inspect directly. Do not scan every frame by default. When an audio stream is present, the tool also attempts bounded waveform/spectrogram attachments for the same window; use `analyzeAudio: false` only when visual-only triage is intentional.

## Audio

Read duration, sample rate, channels, codec, bitrate, and tags. Inspect both waveform and spectrogram attachments before trying Morse, DTMF, hidden-band, or speech decoding. For a localized audio clue, rerun with `signalStartTime` and `signalDuration`; inspect the returned `signalWindow` and widen it if the clue may cross a boundary. Waveform/spectrogram renders are attempted before the raw audio attachment, so a large source file cannot silently consume the whole evidence budget. When signal rendering is enabled, the local bounded signal probe also reports silence boundaries and cautious pulse-timing candidates; these are routing hints for Morse/DTMF/FSK review, not decoded payloads. Treat transcription as optional capability; do not invoke an unconfigured remote service.

## Fallbacks

Missing ffmpeg/ffprobe/tesseract/zbarimg is a capability gap, not a failed solve. Preserve the original, report the missing dependency, and continue with available metadata or ask for an external viewer. Keep attachment size and frame count bounded. The default combined attachment budget is 16 MiB; use `maxTotalAttachmentBytes` for a stricter per-call budget, and inspect `attachmentBudget.skipped` before concluding that evidence is absent. If `capabilities.barcode.available` is false, use the documented fallback (`OpenCV`/`pyzbar` or a bounded `ctf-qr-probe`) rather than treating "no decode" as "no QR".

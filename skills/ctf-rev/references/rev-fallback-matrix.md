# Rev Fallback Matrix

Use this when a reverse engineering branch stalls. Pick exactly one fallback that improves the validation path, exact semantics, or verification oracle.

| Failed Stage                                                                                                             | Symptom                                                                                            | Fallback                                                                                                                                                         | Stop / Pivot Rule                                                                 |
| ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Artifact Triage                                                                                                          | File type or runtime unclear                                                                       | Identify format, architecture, packer/runtime, dependencies, and execution method                                                                                | If not rev-shaped, route to misc/forensics/pwn                                    |
| Facade Capability                                                                                                        | ctf-rev-analyze identifies Mach-O/DEX/JVM/WASM/PYC but the selected tool is unavailable            | Follow the emitted capability/                                                                                                                                   |
| Capability Probe                                                                                                         | Route requires external tools, Python modules, Docker/WSL, ADB, or an optional pack                | Run `ctf-rev-capability-check` and follow `status`, `blocking`, `fallbacks`, and `recommended_path`                                                              | Never execute the target merely to test whether a capability exists               |
| extToolHint; use otool/llvm-objdump/Ghidra, Android pack tools, or the family reference as appropriate                   | Do not force an ELF/PE probe or claim a route was fully analyzed; record the unavailable pack/tool |
| Closure Planning                                                                                                         | Checker/transform primitive is identified but next action is ambiguous                             | Run base-pack ctf-rev-closure-ladder, keep the ledger, and add only oracle-backed probes to decision state                                                       | Do not promote a closure without a confirm oracle or falsification condition      |
| Runtime Rehosting                                                                                                        | Static checker is known and a payload/state dump is required                                       | Request                                                                                                                                                          |
| ev-heavy tools; use rgvJson for live dump arguments, then verify generated Unicorn replay against one native observation | Treat dump/replay builders as generators, not executors; never reintroduce eval                    |
| Flutter AOT Detection                                                                                                    | libapp.so + libflutter.so present                                                                  | Run `flutter_aot_triage` → `flutter_aot_recover` (Blutter) → search asm/ for checker patterns                                                                  | Do NOT attempt manual Ghidra cross-ref on libapp.so without Blutter symbols   |
| Validation Discovery                                                                                                     | No checker found                                                                                   | Xref success/failure strings, input prompts, compare imports, crypto/hash imports, exit paths                                                                    | After two broad decompiler passes, stop and use xrefs/trace                       |
| Entry Confusion                                                                                                          | Main is noisy or framework-generated                                                               | Find user-controlled input boundary and nearest custom code; for Go/Rust use string xrefs and call graph hints                                                   | Do not fully read framework boilerplate                                           |
| Constants Extraction                                                                                                     | Tables/bytes hidden in data/resources                                                              | Dump nearby rodata/resources/assets, decode obvious base/xor/compression, inspect constructors/init arrays                                                       | If constants are runtime-built, switch to trace or instrumentation                |
| Semantics                                                                                                                | Decompiler output ambiguous                                                                        | Verify assembly for signedness, width, truncation, endianness, rotations, and loop bounds                                                                        | Treat pseudocode as hypothesis until verified                                     |
| Solver                                                                                                                   | Manual inversion stalls                                                                            | Write an executable checker/emulator first, then brute force/z3/invert piecewise                                                                                 | Do not solve long logic only in prose                                             |
| Crypto-like Logic                                                                                                        | Looks like TEA/AES/hash/custom cipher                                                              | Identify constants, block size, rounds, mode, key schedule, and compare point                                                                                    | If standard primitive confirmed, use known inverse/attack instead of manual loops |
| Anti-analysis                                                                                                            | Debugger/emulator blocked                                                                          | Prefer static bypass, patch condition, environment stub, or targeted trace of validation only                                                                    | Avoid broad dynamic runs outside sandbox                                          |
| Windows Packed PE                                                                                                        | UPX/section rename unpack fails, rebuilt PE has too few functions             | Use `ctf-pe-unpack`/`ctf-runtime-dump` to rebuild from memory; run `ctf-memstr`, `ctf-rev-pe-recovery`, and `ctf-windows-debug-helper` for cdb/WinDbg automation | Do not manually reverse the packer stub or run one full linear disassembly        |
| Mobile Bridge                                                                                                            | APK/JAR uses JNI/reflection/assets                                                                 | Map manifest/activity, Java xrefs, native exports, asset decryptors, and bridge arguments                                                                        | Start Frida only after target method/native call is known                         |
| VM/Obfuscation                                                                                                           | Dispatcher/bytecode found                                                                          | Identify bytecode blob, opcode table, dispatch loop, handler semantics, and trace oracle                                                                         | Do not fully deobfuscate before extracting trace/check semantics                  |
| Final Verification                                                                                                       | Candidate not accepted                                                                             | Recheck encoding, newline, wrapper format, signedness, byte order, and exact comparison length                                                                   | Do not guess flags; verify or report need for missing runtime                     |

High-information fallbacks:

- Xrefs from success/failure strings beat broad decompilation.
- Executable checker extraction beats manual pseudocode solving.
- Assembly verification beats trusting decompiler arithmetic.
- Targeted dynamic trace beats full instrumentation.
- Mobile static bridge mapping beats blind Frida hooks.

## Runtime session invariant

Use a single workspace-relative `rev_runtime_session.v1` for runtime rehosting branches. Initialize it before generating dump/replay helpers, pass the same `sessionPath` to all Rev runtime tools, and record payload/marker/closure artifacts there. Import native/replay/comparison results with `record-observation`, then run `inspect-artifacts` to refresh size/SHA-256. A changed artifact is `stale`, a deleted artifact is `missing`, and both require review; either state blocks promotion until repaired or re-recorded. Generated helpers are not executors and a replay that starts is not an oracle. Follow the stage ladder; the compatibility direct-promotion path still requires an already-recorded passing oracle. Only an independent `oracle.status=pass` with written evidence plus linked observations may promote the session to `oracle_verified` or `closed`; otherwise keep the route at `planned`/`prepared`/`captured`/`replayed` and document the next falsifiable probe. For new high-confidence branches, use `observationContract=strict`; strict mode requires direct passing native, replay, and comparison observation links. `legacy` remains the compatibility default and `linked` validates links when supplied. Before strict promotion, run `inspect-provenance` to audit both directions of artifact provenance, then use `record-runtime-fingerprint` / `verify-runtime-fingerprint` for externally supplied substrate metadata. A matching fingerprint is consistency-verified only; an unavailable or mismatching runtime is never treated as verified. Finally run `verify-history`: every new event must have a matching SHA-256 `event_hash` and `previous_hash` link. A hashless legacy history remains readable and is reported as `legacy`; it is not cryptographically verified and must not be described as tamper-protected. Strict comparison records must contain at least one semantic result field and reject conflicting output/payload/register/memory/trace digests, exit codes, or stop PCs. Artifact-backed observations should carry artifact generation and SHA-256 snapshots so same-path replacement is detected.
